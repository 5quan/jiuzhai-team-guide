# 九寨同行 · 团队行程手册

可部署的前后端网页，适合团队在手机或电脑打开同一份攻略。Node.js 后端提供共享行程与景点 JSON，原生 HTML/CSS/JS 前端展示。不需要数据库、npm 第三方包或 Windy API Key。

## 功能

- 2026年10月29日晚抵达，30日、31日完整游览；29、30两晚住景区周边镇子，31日游玩后搬到黄龙九寨站附近酒店。新返程日期、车次和航班待定。
- 全幅山水导览图为主画面，当天行程作为浮层叠在留白处；电脑和手机均可收起行程、查看全图，不再将地图限制在侧栏。
- 日期和上午 / 午间 / 下午 / 全天切换，按预计钟点显示当日行程。点击一段或具体地点，地图定位并高亮，避开浮层；地图点选也会关联相应日程。
- 两天的顺序、交通和逐段分钟数按用户提供的“两天休闲版”逐行录入：第一天树正到火花海乘车，第二天固定60分钟内侧栈道，原始森林50分钟、箭竹海40分钟。对应清单见 docs/reference-itinerary.md。
- 默认按参考图10:00入园累计，预留40分钟午餐，预计第一天16:22、第二天17:17出沟。可调整入园时间；钟点只是规划估算，不能当作车辆时刻表。
- 37个景点、细节和设施点，15组蓝色水面，支持搜索、地图缩放、单指或鼠标拖动、键盘选择与全图复原。
- 保留天气、出行须知、住宿接送说明、分享和打印。天气按需加载并在退出时卸载，首页没有第三方字体、地图或定位请求。
- 打印显示三天43项完整安排及全图，包含两天36段参考行程。第三晚住宿和道路接送费用另行确认。

当前是**只读共享页**，无登录、在线编辑、队员信息收集或公开写入接口。不要把身份证、乘机人资料、私人电话等填入公开数据。需要访问控制时，可在自己的反向代理前添加团队访问密码；首版没有自动添加密码。

## Docker 部署（推荐）

服务器安装 Docker Engine 与 Compose 插件，把本项目整个目录上传到服务器。

```sh
cd jiuzhai-team-guide
docker compose up -d --build
docker compose logs --tail=30 guide
```

打开 `http://服务器IP:3000`，并在服务器防火墙 / 云安全组放行所选端口。若需要改端口：

```sh
GUIDE_PORT=8080 docker compose up -d --build
```

服务健康检查：`http://服务器IP:3000/api/health`。停止：

```sh
docker compose down
```

容器使用普通 `node` 用户、只读根文件系统、只读数据挂载，并去除了额外 capabilities。默认限制0.5核CPU、256MiB内存（不额外使用swap）、64个进程，日志总量约10MB。镜像构建需要拉取 `node:24-alpine`，请定期用 `docker compose build --pull` 更新安全补丁。实际构建验证见 `VERIFICATION.md`。

### 绑定域名和 HTTPS（可选）

可通过已有 Nginx 反向代理整个域名根路径到 `http://127.0.0.1:3000`。示例（将域名和证书替换为自己的配置）：

```nginx
server {
    listen 80;
    server_name guide.example.com;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

TLS 证书请通过自己现有的服务配置。应用静态路径和API以 `/` 为根，首版不支持直接挂载到 `/guide/` 子路径。已有反向代理时，可以把 Compose 的端口绑定改成 `127.0.0.1:3000:3000`，避免直接暴露额外端口。

## 本地直接运行

Node.js 22及以上，推荐24。无需 `npm install`。

```sh
npm start
```

打开 `http://localhost:3000`。环境变量：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `3000` | 服务端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `GUIDE_FILE` | `data/guide.json` | 共享攻略数据路径 |
| `GUIDE_PORT` | `3000` | Docker主机对外端口 |

## 更新酒店、接送与日程

编辑 `data/guide.json`，等待约1秒后刷新网页即可读取最新内容，不需要重建镜像或重启。请保持 JSON 格式正确；推荐先修改副本、运行检查后替换，避免写入过程中被读取。

- `trip.hotel`：酒店名称、位置说明。
- `days[].events`：集合时间、车次、航班与确认状态。
- `pending`：待落实事项（首版不会自动把预订状态改成已完成）。
- `park`：官方公告参考时间、来源及提醒。
- `spots`：景点介绍、建议停留时间、示意图坐标（非经纬度）。
- `sources`、`checkedAt`：资料链接和最后人工核对日期。

所有访问同一服务的队员共享同一份数据；修改浏览器界面不会写入服务器。编辑数据后可以执行 `npm test`，再刷新网页核对。

## API

| 路径 | 返回 |
| --- | --- |
| `GET /api/health` | 服务运行状态 |
| `GET /api/guide` | 全部公开行程、景点、来源与计算费用 |
| `GET /api/spots` | 景点列表 |
| `GET /api/weather?layer=clouds` | 官方嵌入地址与完整预报链接 |

图层参数支持 `clouds`、`rain`、`temp`、`wind`。`/api/weather` **不是天气数值接口**，不会伪造、抓取或缓存 Windy 天气。所有接口只支持 GET / HEAD，没有写入或管理员端点。

## 安全与访问量

- 应用仅允许GET/HEAD；不接收请求体，不提供上传、管理、数据库或系统命令接口。静态文件仅允许前端4个固定文件，保留真实路径边界检查。
- 每个TCP来源IP每60秒最多120个请求，实例总计600个请求；超过返回429和Retry-After。IP计数表最多1024项，不信任客户端传来的X-Forwarded-For / X-Real-IP，无法靠伪造这些头绕过限流。固定窗口切换处仍可能短时突发。
- 后端将攻略JSON、天气链接和静态响应缓存1秒，合并同时读取并复用ETag；随机查询参数不增加缓存条目。这里缓存的是攻略和链接，不是Windy实时天气。静态文件改变最多约1秒生效。
- 最大64个连接，请求头8KiB、URL2048字符、请求头等待5秒、请求接收与空闲连接10秒、keep-alive5秒、每连接100次请求。慢连接与错误请求在HTTP解析阶段仍会消耗少量资源。
- 经Nginx/CDN转发时，后端看到的是代理IP，多个队员会共享120次/分钟限制。这是保守默认值；如需更高访问量，应在可信代理配置按真实来源限流，同时阻止绕过代理直连。不要直接改为相信任意转发头。
- 这套配置用于7人团队。资源上限降低单容器影响，但不能保证服务器其他业务不受影响；大流量DDoS或带宽费用需要云厂商防护、带宽/流量告警和必要的CDN/WAF。没有对线上服务进行压力测试。
- 当前HTTP入口没有传输加密；有域名时建议配置HTTPS。GitHub仓库私有不等于网页私有，知道地址的人仍可读取全部行程。需要保密时在反向代理加团队认证并使用HTTPS。

检查结果、已加固内容与未验证项见 `SECURITY-REVIEW.md`。本地源码加固后需重新部署才会影响线上服务。

### 已知边界

1. Windy 和官方导览页是外部服务，队员浏览器需要能访问对应网站。外部内容不加载时，可使用完整预报链接、官方导览链接；自绘示意图与日程仍可用。本轮官方导览页面内的图片地址返回404，首版不加载已知失效地址，保留官方页面入口。未来有可用原图时，可设置 `map.officialImage` 为允许加载的 `https://www.jiuzhai.com` 图片地址。
2. 页面首次加载本身需要本地服务在线，首版没有离线缓存或 PWA。打印保存只包含行程和路线，不包含实时天气。
3. 横向三沟图为关系示意，留白与点位疏密适配画面；不按地理比例绘制，不提供实测定位或导航。官方原图按需直接加载，未将其再分发到项目中。
4. 开放时间来自2026-09-28公告，不是对2026-10-30/31营业时间的保证。实际开园、停靠站、末班车和栈道开放以当日官方安排为准。
5. 两天票按7名无优惠成人测算；有效期依据2025年官方公告，出行前复核官方下单产品。没有确认旺季次日优惠。
6. 29日晚抵达、两个全天游览及31日晚住车站附近已由用户确认；到达车次、具体酒店与接送、新返程日期、车次及航班均待定。
7. 分享复制在 HTTPS 或 localhost 下通常可用；普通 HTTP 浏览器限制剪贴板时，会提示复制地址栏。
