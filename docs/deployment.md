# 部署与维护

这是一个只读的两天行程参考手册，使用Node.js提供本地页面与行程数据，不需要数据库或安装第三方npm包。

## 运行

需要Node.js 22及以上，推荐24。

```sh
npm start
```

默认打开http://localhost:3000/。健康检查为/api/health。

## Docker部署

```sh
docker compose up -d --build
docker compose ps
```

默认端口3000，可以通过GUIDE_PORT环境变量指定主机端口。项目现有服务器使用666端口。已有.env与数据挂载应在发布时保留，不纳入Git。

## 更新行程

编辑data/guide.json，包含两天行程、景点、交通与示意坐标。数据约1秒内重新读取，刷新即可查看；前端样式或逻辑修改后需要重建服务。先运行检查，写入完整有效的JSON，再替换线上文件。

```sh
npm run check
npm test
```

详细的当前安排见[行程参考表](reference-itinerary.md)。地图是关系示意，钟点是规划估算；天气内容由第三方天气页面提供。

## 版本与发布

- 当前网页版本web0.1.0，对应package.json版本0.1.0；可通过页面application-version元信息核对版本。
- 版本说明保存在[CHANGELOG.md](../CHANGELOG.md)，已发布标签不移动或覆盖，后续修改使用新版本号。
- 发布前核对线上源码是否被其他会话更新，并保存源码和容器镜像备份。
- 发布后核对健康接口、手机布局、行程点选和资源版本。回滚时使用该版本源码与镜像；涉及数据变更时同时恢复对应行程数据。

入园时间、酒店、个人资料等实际出行安排由使用者维护，不要向公开仓库写入私人证件、电话或订单信息。
