# 需求记录 · 2026-10-21

这份文件记录本轮对话里提出的需求、做出的决定和还没做完的事。按时间顺序，方便回头查「当时为什么这么做」。

## 产品目标（用户原话）

> 朋友在景区游玩时，愿意主动向 AI 分享照片、语音和感受；AI 能结合当前旅行及之前的分享，给出具体、自然、有连续性的回应。
>
> 核心卖点是：下一次旅行，还能带上同一个记得你的 AI。

## 需求清单

### 对话内核

1. 修复 `lib/chat.mjs` 到可运行（当时缺 `readBody` / `upstream` / `cookie`）
2. 三层记忆：事实（facts）+ 情景（episodes）+ 原文，每 5 轮异步抽取
3. 记忆治理：更新保留旧值、用户要求忘记时真删并留墓碑、越权 id 丢弃
4. `/memory` 页面：能看、能删
5. 分段流式：一句一句出，带打字指示，可停止
6. 图片：发送、压缩去 EXIF、落盘、鉴权访问
7. 表情包：`<meme:分类>` 标记，服务端剥离后选图
8. 主动消息：默认关闭，按行程情景生成，每天上限 2 条、夜间不发
9. 联网搜索：实时问题触发 DeepSeek Search，失败静默
10. 首次进入聊天由模型主动问称呼（只生成一次）

### 界面与体验

11. 开屏动画：用用户给的 GIF，播放 2.5 秒后渐隐，可点击跳过，同会话不重复
12. 底部导航：从四项精简为「行程 / 聊天」，地图不再是独立栏目
13. 首页右下角常驻聊天挂件（Q 版头像，点击进聊天）
14. 对话头像：从全身立绘抠出人物，不带圆框
15. 输入框：微信式单行起，随内容增高到 120px
16. 主页天气：现在温度/天气 + 下一小时预报
17. 行程时长文案：`50分钟` → `游览50分钟`
18. 聊天入口红点：AI 主动发话且未读时显示
19. 主要面向手机端

## 中途修正过的判断

| 一开始的判断 | 实际 | 怎么发现的 |
|---|---|---|
| 本机没有 Playwright | **有**，在 `D:\project\fun\shot\node_modules\playwright` | 用户提醒后重查；之前只查了几个固定路径 |
